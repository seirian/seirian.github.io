업무 시스템 · 환경 관리CASE 01

대기운영일지
운영 데이터 입력 규칙과 화면 개선

가동시간과 전력사용량 사이의 일관성을 유지하고, 일괄 입력과 표준 엑셀 양식까지 고려한 업무 화면의 개선 과제입니다.

문제 / 과제

가동 여부와 운전 데이터가 서로 모순되거나, 업무 상황에 맞는 입력 흐름이 부족할 경우 데이터 품질이 저하될 수 있습니다.

주요 기술적 검토

출구번호 기준 매핑, 조건별 입력 검증, 중지시간을 반영한 산식, 탭별 UI 제어와 엑셀 양식 대응.

구체적인 개발 범위 보기+
  • 가동시간이 0인데 전력사용량을 입력하거나, 가동시간이 있는데 사용량이 0일 때 유효성 경고
  • 종료·시작시간과 중지시간을 분리하여 실가동시간 계산
  • 운전사항 탭의 미가동 체크 및 전일·당일 지침 자동 설정
  • 가동시간·운전사항을 SEMS 표준 엑셀 양식으로 구분
  • 보수내역 탭 추가와 탭별 상단 입력 영역의 조건부 표시

업무 시스템 · 데이터 전환CASE 02

수질운영일지
AS-IS → TO-BE DB 구조 전환 대응

신규 DB 이전으로 테이블명·컬럼명·데이터 타입이 변경되는 상황에서, 기존 수질운영일지 화면과 전체 로직이 새로운 구조와 일치하도록 조정하는 과제입니다.

문제 / 과제

레거시 테이블 구조에 종속된 조회·입력·저장 로직이 신규 스키마와 맞지 않으면 기능 장애와 데이터 불일치가 발생할 수 있습니다.

주요 기술적 검토

변경 매핑 CSV를 기준으로 연관 테이블·컬럼·타입을 비교하고, 참조 지점과 영향 범위를 추적합니다.

구체적인 개발 범위 보기+
  • AS-IS 역테이블·역컬럼·역타입과 TO-BE 테이블명·컬럼명·데이터타입 매핑
  • 조회, 등록, 수정, 상세 기능에 사용되는 SQL/데이터 바인딩 영향 검토
  • 데이터 타입 차이와 누락 컬럼에 따른 예외 처리 검증
  • 공통 개발 규칙과 리뷰 기준을 준수하는 이관 구현

HAPs운영일지
상세 화면 오류 원인 분석

목록에서 상세 버튼을 누를 때 오류 페이지로 이동하는 현상에 대해, 화면 이벤트부터 서버 처리와 데이터 조회 흐름까지 원인을 찾는 유지보수 과제입니다.

문제 / 과제

상세 진입 과정의 오류로 기존 데이터 확인이 불가능해 업무 흐름이 중단되는 상황.

주요 기술적 검토

버튼 이벤트와 라우팅, 요청 파라미터, 상세 조회 API 및 예외 처리 경로를 단계적으로 확인.

분석·검증 범위 보기+

  • 연동 데이터 및 서버 로그 기반 오류 발생 지점 확인
  • 정상 데이터·빈 데이터·예외 데이터의 상세 진입 흐름 검증

↗
02 / DESIGN

변경 영향 범위를 추적합니다.
